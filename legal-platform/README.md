# منصة بيوت مصر للتشغيل القانوني

**بنية تشغيلية لإدارة إنتاج الخدمة القانونية** — وليست «برنامج استشارات قانونية» ولا «WhatsApp Bot».

التسويق يجلب الطلب ← القنوات المختلفة تستقبله ← الـ Intake Engine يحوله إلى بيانات منظمة ← الإدارة تقرر ما يستحق أن يصبح ملفًا وكيف يُدار ← شبكة المحامين توفر الخبرة (منفردة أو في فرق متعددة التخصصات) ← المنصة تدير الصلاحيات والتعاون والمواعيد والتواصل والمحاسبة ← الأتمتة تقلل العمل الإداري المتكرر ← والذكاء الاصطناعي يستفيد من المعرفة المتراكمة ويعيدها إلى دورة العمل.

---

## التشغيل السريع (دقيقة واحدة)

المتطلبات: **Node.js 22.13 أو أحدث** فقط. لا توجد قاعدة بيانات خارجية ولا اعتماديات إلزامية.

```bash
cd legal-platform
node server.js          # أو: npm start
```

ثم افتح:

| الرابط | الوصف |
|---|---|
| `http://localhost:3000/` | الموقع العام للمواطنين (بابان: الموقع وواتساب) |
| `http://localhost:3000/intake` | تقديم الطلب على الموقع (نموذج منظم أو محادثة خطوة بخطوة) |
| `http://localhost:3000/app` | منصة الإدارة وبوابة المحامين |
| `http://localhost:3000/p/<رمز>` | بوابة العميل الخاصة (تُعطى له بعد تقديم الطلب) |
| `/about` · `/privacy` · `/terms` · `/data-deletion` | عن البرنامج، سياسة الخصوصية، شروط الاستخدام، وتعليمات حذف البيانات (مطلوبة لمراجعة تطبيق ميتا) |
| `/robots.txt` · `/sitemap.xml` · `/manifest.webmanifest` | ملفات محركات البحث وتطبيق الهاتف (PWA) للفريق والمحامين |

**الموقع العام (الإصدار 9):** صفحات `public/*.html` قوالب يولّدها الخادم (`src/site.js`) من إعدادات المؤسسة: الرأس والتذييل المشتركان، وسوم Open Graph وTwitter وJSON-LD (NGO + LegalService + FAQPage)، وروابط مطلقة من `PUBLIC_BASE_URL` (أو ترويسة Host). تُعدَّل بيانات التواصل من «الإعدادات ← الموقع العام وبيانات التواصل». المنصة `/app` قابلة للتثبيت على الهاتف: عامل خدمة `sw.js` بنطاق `/app` فقط يخزّن الملفات الثابتة وحدها (لا يخزّن `/api` ولا `/p/` ولا `/portal` أبدًا) ويعرض صفحة «لا يوجد اتصال» عند الانقطاع. عند النشر يتغير إصدار العامل تلقائيًا، ويظهر للمستخدم تنبيه «يتوفر إصدار أحدث» فلا يُفعَّل الإصدار الجديد إلا بضغطه «تحديث الآن» (حتى لا تختلط ملفات إصدارين في صفحة مفتوحة). بيانات التواصل في الموقع تُتحقق في الخادم أيضًا (روابط https من facebook.com/instagram.com فقط، بريد وهاتف صالحان)، وإفراغ أي حقل اختياري يخفيه من الموقع.

عند أول تشغيل في الوضع التجريبي تُنشأ بيانات كاملة تعيد تمثيل السيناريو (إعلان فيسبوك ← واتساب ← الملف `INH-2026-00482` للعميلة `CL-00881` ← المحامي الأساسي ← طلب معلومات ← متخصص ضرائب على «المسألة رقم 3» …)، وتظهر الحسابات التجريبية في صفحة الدخول:

| المستخدم | كلمة المرور | الدور |
|---|---|---|
| `admin` | `Admin@2026` | إدارة النظام |
| `manager` | `Manager@2026` | إدارة الحالات |
| `ahmed` | `Lawyer@2026` | محامٍ — مواريث (المحامي الأساسي في INH-2026-00482، بالقطعة 500 ج.م) |
| `mohamed` | `Lawyer@2026` | محامٍ — ضرائب (محامٍ متخصص مساعد يرى المسألة رقم 3 ومستندين فقط، 250 ج.م) |
| `salwa` | `Lawyer@2026` | مراجعة نهائية (تطوعي دون مقابل) |
| `hany`, `yasmine`, `tarek`, `rania`, `amr` | `Lawyer@2026` | محامون باتفاقات: شهري، شهري بحصة، مسؤولية مجتمعية لمكتب محاماة، باقة، بالقطعة عند الإغلاق |
| `heba` | `Compliance@2026` | إدارة النظام بتحقق بخطوتين — أضف المفتاح التجريبي `BEYOOTMISRDEMOTWOFACTORKEYSECRET` في أي تطبيق مصادقة لتجربة الدخول على خطوتين |

لإعادة إنشاء البيانات التجريبية: `npm run seed -- --yes` (يحذف قاعدة البيانات المحلية).

## كيف تتحقق رؤية المشروع داخل المنصة

### 1) بابان (أو أكثر) لنفس الـ Intake Engine
- **واتساب**: تصل الرسائل من WhatsApp Business Platform إلى `POST /webhooks/whatsapp` (مع التحقق من توقيع ميتا ومنع التكرار)، وتُنزَّل الصور والمستندات والرسائل الصوتية تلقائيًا.
- **الموقع**: `POST /api/public/intake` من صفحة `/intake` (نموذج منظم أو تجربة محادثة أبسط مع رفع المستندات).
- **أبواب إضافية**: الإدارة تسجل طلبات المكالمات والحضور الشخصي والبريد يدويًا؛ وكل قناة جديدة تمر بنفس الدالة `engine.receive()` دون تغيير قلب المشروع.
- **عميل واحد وملف واحد**: يُوحَّد العميل برقم الهاتف عبر كل القنوات. إذا بدأ على الموقع ثم أكمل على واتساب (بنفس الرقم أو بذكر رقم الطلب `REQ-…`) تُلحق الرسائل بنفس الطلب. أما رقم **مختلف** يذكر رقم طلب لعميل آخر فلا يُدمج تلقائيًا حماية للخصوصية، بل تُنبَّه الإدارة.
- **مصدر العميل ≠ قناة التواصل**: إعلان فيسبوك/إنستجرام (من بيانات Click-to-WhatsApp Ads)، جوجل، إحالة من جهة متعاونة (`?ref=`)، دخول مباشر… مع تتبع الحملة.

### 2) الإدارة تقرر (صندوق الوارد الموحد)
- كل رسالة تبدأ «طلبًا واردًا» وليست ملفًا. الذكاء الاصطناعي يجمع الرسائل ويلخصها ويقترح عنوانًا ومجالًا قانونيًا ويستخرج الوقائع ويحدد المعلومات والمستندات الناقصة ويقترح المسائل، ويُنبه: «هذا الطلب يشبه 5 حالات تعاملت معها المؤسسة من قبل».
- القرار للإدارة: رد وتعامل داخلي دون شراء وقت محامٍ، أو أرشفة، أو **تحويل إلى ملف** بكود مستقل مثل `INH-2026-00482` (المجال-السنة-التسلسل)، ويرتبط بالعميل `CL-00881` الذي قد تكون له ملفات أخرى عبر الزمن.

### 3) ما تراه الإدارة ليس بالضرورة ما يراه المحامي
- الإدارة ترى الملف كاملًا: بيانات العميل وهاتفه، المحادثة الأصلية، المستندات، المصدر، الملاحظات الداخلية، السجل، المحامين، التكلفة.
- لكل عضو في فريق الملف **صلاحيات صريحة** (`assignment_grants`): ملخص الوقائع، اسم العميل (اختياري)، مسائل بعينها، مستندات بعينها، آراء أعضاء بعينهم. **لا يحصل المحامي أبدًا** على هاتف العميل أو رقمه القومي أو المحادثة أو مصدره أو التكلفة. كل بيانات بوابة المحامي تُبنى في ملف واحد (`src/services/visibility.js`)، والملفات غير المسندة تعطي 404.
- الفريق: المحامي الأساسي، محامٍ متخصص مساعد، رأي ثانٍ، مراجعة نهائية، محامٍ مشارك، ومدير حالة من المؤسسة. ما تكلّف به الإدارة كل محامٍ يُسمى «إسنادًا» في واجهتي الإدارة والمحامي، و«المهام» للملفات المستمرة فقط.

### 4) المحامي يعمل من داخل المنصة فقط
- يجد الملفات المحالة إليه، والسؤال المطلوب تحديدًا، والموعد المطلوب.
- يكتب رأيه في محرر بحفظ تلقائي للمسودة، ويستعين بمسودة أولية من الذكاء الاصطناعي (مبنية فقط على ما أُتيح له وعلى المعرفة المعتمدة المجهّلة).
- **طلب معلومات / طلب مستند**: يذهب للإدارة أولًا ← توافق وترسل للعميل عبر قناة المؤسسة ← رد العميل يدخل نفس الملف ← تراجعه الإدارة وتتيحه ← يصل للمحامي إشعار.
- **طلب مساعدة محامٍ** (رأي ثانٍ، رأي متخصص، مراجعة مستند، مشاركة): لا يفتح الملف لأحد تلقائيًا؛ الإدارة تختار المحامي من الشبكة (مع ترشيح حسب التخصص والحمل والأداء) وتحدد بدقة ما يراه.
- ضغط «تقديم» لا يعني أن العميل تلقى الرد: الإدارة تعتمد أو تعيد مع ملاحظات، ثم تعد **نسخة موجهة للعميل** (يمكن صياغتها بالذكاء الاصطناعي) وترسلها عبر قناة المؤسسة. **الإغلاق قرار الإدارة وحدها.**

### 5) ملفات العمل المستمر (Matters) والأتمتة
- تحويل الاستشارة إلى ملف مستمر مرتبط بنفس العميل والاستشارة: محكمة، دائرة، رقم دعوى، جلسات، مهام ومواعيد إجرائية، فواتير ومدفوعات ومصروفات.
- الأتمتة مرتبطة بما يحدث داخل الملف: تذكير العميل بالجلسة قبلها بثلاثة أيام إذا كان حضوره مطلوبًا (مرة واحدة لكل موعد)، تذكير بالفواتير المتأخرة، تذكير بالمستندات الناقصة، تنبيه بموعد إجرائي يقترب، وتنبيه بتأخر المحامي.

### 6) المحاسبة داخل نفس المنظومة
اتفاق كل محامٍ جزء من ملفه: **بالقطعة** (مثل 500 ج.م لكل استشارة معتمدة)، **شهري ثابت**، **شهري بعدد استشارات + سعر للزيادة**، **باقة مدفوعة مسبقًا** (تُخصم منها الاستشارات المعتمدة)، **تطوعي بالكامل دون مقابل**، أو **برنامج مسؤولية مجتمعية لمكتب محاماة** (عدد استشارات/ساعات). وحدة المحاسبة في كل الاتفاقات هي «الاستشارة المعتمدة». واقعة الاستحقاق قابلة للضبط (عند الاعتماد أو عند الإغلاق)، وكل عضو في الفريق يُحاسب مستقلًا (مثلًا: الأساسي 500، المتخصص 250، المراجعة النهائية تطوعًا). تعرف الإدارة تكلفة كل ملف فعليًا (مباشرة + مصروفات + حصة تقديرية من الاتفاقات الشهرية والباقات + قيمة المساهمات التطوعية)، وأي أنواع الملفات تحتاج أكثر من تخصص.

### 7) شبكة المحامين كطاقة قانونية قابلة للتوسع
لكل محامٍ: التخصصات، الطاقة الاستيعابية، الملفات المفتوحة، المتأخرات، متوسط زمن الرد، المنجز خلال الشهر، نسبة الإعادة، تقييم الجودة، الاستشارات التطوعية، والمستحقات.

### 8) المعرفة المؤسسية والذكاء الاصطناعي
- المنصة لا تحفظ الإجابة النهائية فقط بل **رحلة التفكير والتصحيح**: ماذا فهم الذكاء الاصطناعي، كيف صححته الإدارة، ما الذي طلبه المحامي، متى احتاج متخصصًا، ما الذي أعيد للتعديل، وما الإجابة المعتمدة.
- عند الإغلاق يُبنى سجل معرفة مع **إخفاء البيانات الشخصية** (الأسماء المعروفة، الهواتف، الأرقام القومية، البريد، العناوين، أكواد الملفات)، ويبقى «بانتظار المراجعة» حتى تعتمده الإدارة للاسترجاع المعرفي فقط أو للاسترجاع والتدريب وقياس الأداء. يمكن تصدير الحالات المعتمدة للتدريب بصيغة JSON.
- كل تصحيح من الإدارة أو المحامي يُسجل تغذيةً راجعة، وتعرض المنصة دقة الذكاء الاصطناعي في كل وظيفة (التصنيف، العنوان، النواقص، الحاجة لمتخصص، المسودات) عبر الزمن.

### 9) العمل الأهلي والممارسة القانونية (الإصدار 9)
- **بطاقة المستفيد (البحث الاجتماعي)** في ملف العميل وشاشة فرز الطلب: صفة المستفيد (أرملة، وصي أو كافل أيتام، مطلقة معيلة …)، الأبناء بسنة الميلاد والنوع فقط (بلا أسماء)، الدخل والسكن والعمل، ورقم الملف لدى المؤسسة، مع **درجة احتياج شفافة بأسبابها** واقتراح رفع أولوية الطلب. ما يذكره مقدم الطلب في نموذج الموقع (`beneficiary` في `POST /api/public/intake`) يُحفظ «غير موثّق» ولا يمس أبدًا بطاقة عميل قائم برقم غير موثّق. لا يرى المحامون شيئًا منها.
- **تقرير الأثر** (`/impact`) للمجلس والجهات المانحة ووزارة التضامن: الأسر المخدومة، الأرامل والأبناء، نتائج الملفات، **قيمة الحقوق المستردة** (دفعة واحدة وشهريًا وسنويًا — تُسجل عند إغلاق الملف أو بعده)، التوزيع حسب المجال والمحافظة والشهر، قيمة العمل التطوعي، زمن الاستجابة، ورضا المستفيدين؛ قابل للطباعة والتصدير CSV.
- **تعارض المصالح**: أطراف كل ملف (خصم، طرف ذو صلة، شاهد) تُفحص تلقائيًا — بتوحيد صيغ الأسماء العربية والرقم القومي — مقابل كل العملاء وأطراف الملفات الأخرى عند تحويل الطلب وإضافة الطرف وتسجيل خصم الملف المستمر، مع تحذيرات غير مانعة وصفحة بحث يدوي (`/conflicts`).
- **التقويم** (`/calendar` و`/my/calendar` للمحامي): الجلسات والمواعيد الإجرائية ومواعيد تسليم الإسنادات واستحقاق الفواتير، عرض شهري وجدول مواعيد، و**اشتراك تقويم الهاتف** برابط ICS سري لكل مستخدم (آيفون / Google / Outlook) لا يتضمن بيانات اتصال المستفيدين، ويتوقف تلقائيًا عند إيقاف الحساب أو تغيير كلمة المرور أو تعيين كلمة مرور مؤقتة.
- **مستوى الخدمة**: زمن أول رد من الإدارة على كل طلب (واتساب والموقع)، ومهلة قابلة للضبط (`sla_first_response_hours`، افتراضيًا 4 ساعات) مع تنبيه للإدارة مرة واحدة لكل طلب متأخر، ومؤشران في لوحة المتابعة.
- **البحث الشامل** `Ctrl/⌘+K` من الشريط العلوي: الإدارة في العملاء والطلبات والملفات والمحامين، والمحامي في إسناداته وملفاته فقط.
- **الاستيراد والتصدير** (`/data`، مدير النظام): تصدير CSV متوافق مع Excel بالعربية، واستيراد المحامين والعملاء/المستفيدين بخطوة معاينة تتحقق من كل صف، ثم تُضاف الصفوف السليمة في معاملة واحدة؛ وكل عملية تُسجل في سجل الأمان. حسابات المحامين المستوردة تُنشأ «بانتظار الدعوة» (بلا كلمة مرور صالحة) وتُصدر لها الإدارة روابط الدعوة من صفحة كل محامٍ.

### 10) البرامج والتمويل والمستندات المطبوعة (الإصدار 9)
- **البرامج ومصادر التمويل** (`/programs`): منحة، زكاة «نماء»، شراكة مسؤولية مجتمعية، تبرعات، موارد ذاتية؛ لكل برنامج ميزانية ومدة ونطاق أهلية (مجالات ومحافظات) وقيود صرف. **الملف ينتمي لبرنامج واحد على الأكثر** ويتبعه ملفه المستمر؛ يُربط من صفحة البرنامج أو صفحة الملف أو عند تحويل الطلب، والربط خارج النطاق أو النقل من برنامج آخر يحتاج تأكيدًا صريحًا ويُسجل في سجل الملف. **البرنامج المغلق سجل نهائي**: لا تُضاف إليه ملفات ولا تُنقل منه حتى يعيد مدير النظام فتحه.
- **الإنفاق الفعلي** = أتعاب المحامين المستحقة على ملفات البرنامج (بالقطعة، الزيادة، أتعاب الملف المستمر، التسويات) + استرداد مصروفاتهم + المصروفات التي دفعتها المؤسسة، خلال مدة البرنامج؛ مع المتبقي ومعدل الإنفاق الشهري والمتوقع حتى نهاية المدة، والأسر والملفات المخدومة ونتائجها، و**تقرير مطبوع للجهة الممولة بلا أسماء مستفيدين**.
- **تنبيهات الميزانية** للإدارة عند 80% و100% (قابلة للضبط من «إعدادات التنبيهات والطباعة» في صفحة البرامج)، مرة واحدة لكل نسبة ولكل قيمة ميزانية: فور اعتماد رأي محامٍ أو إغلاق ملف في البرنامج، وعند الربط والتعديل، وبمهمة دورية كل ساعة.
- **المستندات المطبوعة** (`#/print/:kind/:id` على ورقة A4 بترويسة المؤسسة وترقيم «صفحة X من Y»، مع حفظ PDF من نافذة الطباعة): الفاتورة (والمبلغ بالحروف)، **إيصال الاستلام برقم ثابت `RCPT-YYYY-NNNNN`** يصدر عند تسجيل الدفعة، **الإفادة القانونية** باسم المؤسسة وحدها (بلا اسم محامٍ ولا هاتف المستفيد)، كشف حساب المحامي لفترة (للمحامي نفسه أو لمدير النظام)، ملخص الملف الداخلي، وتقرير البرنامج. كل مستند يفرض صلاحيات بياناته الأصلية في `GET /api/print/:kind/:id` (المحامي يحصل على 404)، وكل طباعة أو محاولة مرفوضة تُسجل في سجل الأمان.

## الذكاء الاصطناعي

- **افتراضيًا** يعمل «محلل محلي» بقواعد عربية بدون إنترنت (يفهم العامية المصرية الشائعة): تصنيف، عنوان، ملخص، وقائع، نواقص حسب المجال، مسائل مقترحة، أولوية، وبحث تشابه بالمقاطع الحرفية.
- **مع Claude**: ثبّت الحزمة الاختيارية (`npm install`) واضبط `ANTHROPIC_API_KEY`. النموذج الافتراضي `claude-opus-5-5` (يمكن تغييره بـ `AI_MODEL`)، مع مخرجات JSON منظمة وإعادة توجيه تلقائية عند الرفض. عند أي تعذر يعود النظام تلقائيًا إلى المحلل المحلي دون توقف.
- المسودة الآلية للمحامي تعتمد **فقط** على ما أتاحته الإدارة له، والحالات المشابهة المعروضة للمحامين **مجهّلة ومعتمدة** فقط.
- **الإعداد من لوحة الإدارة (الإصدار 9)**: المفتاح والنموذج ومستوى الجهد ووضع التشغيل (تلقائي / Claude / محلي) وسقف الإنفاق الشهري تُضبط من «التكاملات» وتُطبق فورًا دون إعادة تشغيل (متغيرات البيئة تتقدم إن ضُبطت). زر «اختبار الاتصال» يرسل طلبًا صغيرًا حقيقيًا ويعرض الخطأ بالعربية (مفتاح غير صالح، تجاوز حد الاستخدام، ازدحام الخدمة، تعذر الشبكة).
- **الاستهلاك والتكلفة**: كل استدعاء يُسجَّل (الوظيفة، الرموز، الذاكرة المؤقتة، النموذج، زمن الاستجابة، الخطأ) مع تكلفة تقديرية بجدول أسعار في `src/ai/anthropic.js`. عند بلوغ السقف الشهري يعود النظام تلقائيًا إلى المحلل المحلي ويُخطَر مديرو النظام مرة واحدة في الشهر (وتحذير عند 80%). اللوحة في «المعرفة المؤسسية ← أداء الذكاء الاصطناعي» و`GET /api/admin/ai/usage`.
- **ردود مقترحة للإدارة** (`POST /api/admin/ai/suggest-reply`): ردان أو ثلاثة جاهزة لواتساب مبنية على المحادثة والنواقص والطلبات المرسلة والرد المعتمد فقط، بلا أسماء محامين أو ملاحظات داخلية أو استنتاجات قانونية غير معتمدة.
- **تحليل المستندات** (`POST /api/admin/ai/documents/:id/analyze`، وللمحامي على المستندات المتاحة له فقط): نوع المستند، الوقائع الرئيسية، ما يثبته، الملاحظات (منتهٍ، غير واضح، صفحات ناقصة) والمستندات المرتبطة الناقصة. لا يُرسل أي مستند لخدمة خارجية دون تفعيل Claude؛ وبدونه تصنيف مبدئي من اسم الملف. الحد الأقصى للإرسال: الصورة 3.75 ميجابايت وملف PDF 22 ميجابايت (حدود الخدمة بعد ترميز base64)، وما يتجاوزه يُصنَّف مبدئيًا. تُحذف أرقام الهواتف من نتيجة التحليل المحفوظة (بالأرقام العربية أو اللاتينية)، وتُخفى الأرقام القومية عما يراه المحامي.
- **الاسترشاد بالمعرفة المعتمدة**: مسودة المحامي والنسخة الموجهة للمستفيد تستعينان بأقرب الحالات المعتمدة المجهّلة وتحليلات المستندات، وتُذكر في المسودة الحالات المستخدمة («استُرشد بـ: KR-…»).
- مجالان لعمل المؤسسة مع الأرامل والأيتام: **GRD** الولاية على المال والنيابة الحسبية، و**PEN** المعاشات والتأمينات وتكافل وكرامة (بمعجم وقوائم نواقص ومسائل مقترحة).

## ربط واتساب الحقيقي (WhatsApp Business Platform — Cloud API)

1. أنشئ تطبيقًا على Meta for Developers وأضف منتج WhatsApp، واحصل على `Phone Number ID` و Token دائم (System User).
2. اضبط في `.env`: `WHATSAPP_TOKEN`، `WHATSAPP_PHONE_NUMBER_ID`، `WHATSAPP_VERIFY_TOKEN` (نص تختاره)، `WHATSAPP_APP_SECRET`، `WHATSAPP_NUMBER`.
3. في إعدادات Webhook على ميتا: الرابط `https://<نطاقك>/webhooks/whatsapp` ونفس رمز التحقق، واشترك في حقل `messages`.
4. **نافذة الـ 24 ساعة**: خارجها لا يسمح واتساب إلا برسائل «قوالب» معتمدة. أنشئ قالبًا من فئة Utility باسم `case_update` (أو غيّر الاسم من الإعدادات) بلغة العربية، ونصه متغير واحد `{{1}}`؛ تستخدمه المنصة تلقائيًا للتذكيرات والردود خارج النافذة.
5. بدون هذه القيم تعمل المنصة في **وضع المحاكاة**: تُسجل الرسائل الصادرة بحالة «إرسال تجريبي»، ويمكن تجربة الوارد من «محاكي واتساب» داخل المنصة (يبني Webhook مطابقًا لصيغة ميتا ويمرره على نفس المسار).

## التشغيل في بيئة الإنتاج

```bash
NODE_ENV=production DEMO=0 ADMIN_USERNAME=admin ADMIN_PASSWORD='كلمة-مرور-قوية' \
PUBLIC_BASE_URL=https://legal.example.org TRUST_PROXY=1 node server.js
```

- أو عبر Docker: `docker build -t bayout-legal . && docker run -p 3000:3000 -v bayout-data:/app/data --env-file .env bayout-legal`
- **احفظ المجلد `data/` في نسخ احتياطية** (قاعدة SQLite + المرفقات). كل الكتابات معاملات ذرية (WAL).
- ضع المنصة خلف HTTPS (Nginx أو منصة استضافة)، واضبط `PUBLIC_BASE_URL` بـ https لتفعيل الكعكات الآمنة.
- `TRUST_PROXY=1` آمن فقط خلف وكيل يضيف `X-Forwarded-For`؛ يُقرأ عنوان العميل من يمين الترويسة بعدد الوكلاء `TRUST_PROXY_HOPS` (افتراضيًا 1). لا تفعّله عند كشف المنفذ مباشرة.
- في الإنتاج أو عند ضبط بيانات واتساب الحقيقية يجب ضبط `WHATSAPP_APP_SECRET`؛ بدونه يرفض النظام كل رسائل Webhook (لا تُقبل الرسائل غير الموقعة إلا في وضع المحاكاة).
- كل الإعدادات في `.env.example`.
- **دليل النشر الكامل (الإصدار 9): [`DEPLOY.md`](DEPLOY.md)** — Render (`render.yaml`)، خادم VPS بـ Docker Compose وCaddy، معالج الإعداد الأول `/setup` (بدون `ADMIN_USERNAME`/`ADMIN_PASSWORD` يُطبع رابط الإعداد في السجل)، استرداد حساب المدير `npm run admin`، ربط واتساب وClaude من صفحة «التكاملات»، النسخ الاحتياطي اليومي والتصدير الكامل والاستعادة `npm run backup` / `npm run restore`، وقائمة التحقق قبل الإطلاق.

## الأمان والخصوصية
- الصلاحيات تُفرض في الخادم لكل طلب (وليس في الواجهة)، والموارد غير المتاحة تعطي 404 حتى لا يُكشف وجودها.
- كلمات المرور بـ scrypt، جلسات بكعكات HttpOnly + SameSite، حماية CSRF (JSON فقط + فحص Origin)، CSP صارمة، تحديد معدل الدخول وطلبات الموقع، التحقق من توقيع Webhook واتساب، رفع ملفات بأنواع محددة وحجم محدود مع تنزيل آمن.
- روابط بوابة العميل عشوائية ومخزنة بشكل مُجزّأ (hash) ولها صلاحية زمنية، ويمكن للإدارة إلغاؤها لكل عميل أو لكل طلب.
- **الحسابات (الإصدار 9)**: إنشاء المحامين وموظفي الإدارة بدعوة للاستخدام مرة واحدة (72 ساعة، تُرسل عبر واتساب) بدل تسليم كلمات مرور؛ روابط إعادة تعيين تُنهي كل الجلسات؛ كلمة المرور التي تعيّنها الإدارة مؤقتة ويُلزم صاحبها بتغييرها عند أول دخول؛ تحقق بخطوتين (TOTP وفق RFC 6238 مع رمز QR وعشرة رموز استرداد مُجزّأة، ويمكن إلزام «إدارة النظام» به)؛ إيقاف مؤقت متصاعد بعد 5 محاولات فاشلة وتنبيه حرج للإدارة عند 10؛ مهلة عدم نشاط للجلسات وصفحة «حسابي والأمان» لعرض الأجهزة وإنهائها؛ و«سجل الأمان» لمدير النظام بالتصفية وتصدير CSV.
- رقم الهاتف في نموذج الموقع غير موثّق: رابط البوابة الناتج مقصور على الطلب الجديد وحده، ولا يُتبع رقم طلب مذكور في النموذج. وإذا طابق الرقم عميلًا مسجلًا يظهر تنبيه في صفحة الطلب، ولا تُوجَّه رسائل صاحب الرقم الحقيقية عبر واتساب إلى هذا الطلب حتى تؤكد الإدارة هوية المرسل.
- مرفقات العميل ومستندات الاستشارة لا تظهر للمحامي المسؤول عن الملف المستمر إلا إذا أتاحتها الإدارة صراحة، ونصوص المواعيد التي يكتبها المحامي لا تصل للعميل (تذكيرًا أو في البوابة) قبل اعتماد الإدارة.
- لا تدخل أي حالة في قاعدة المعرفة قبل مراجعة الإخفاء واعتمادها.

## English summary

**Bayout Masr Legal Operations Platform** — an operating system for producing legal services at scale, built from the organization's vision.

- **Unified Intake Engine**: WhatsApp Business Platform webhook + website intake (+ manual phone/walk-in) → one inbox. Cross-channel identity resolution by phone and reference code (with a privacy guard against auto-merging different numbers). Source (ads, Google, referral) tracked separately from channel.
- **Staff decide**: AI-assisted triage (summary, classification, missing info, issues, similar-case alerts) → handle internally / archive / convert to a case coded like `INH-2026-00482`, linked to client `CL-00881`.
- **Fine-grained, server-enforced visibility**: each lawyer on a case team sees only explicitly granted facts, issues, documents and teammates' opinions — never client contact data, the conversation, source or cost.
- **Lawyer portal**: drafting with autosave and AI first drafts, info/document requests and counsel-assistance requests routed through admin, submission for admin review; admin approves/returns, prepares a client-facing version, sends it, and alone closes the case.
- **Matters** (court, hearings, tasks, invoices, payments, expenses) and **event-driven automations** (hearing reminders 3 days before, invoice/document reminders, procedural deadlines, overdue alerts) over WhatsApp (or simulation).
- **Accounting** per lawyer agreement (per-case, monthly, monthly quota + overage, prepaid package, pro bono, law-firm CSR), configurable billable event, independent billing per team member, true cost per case, payouts and month closing.
- **Knowledge pipeline**: closed cases become anonymized records (PII redaction + mandatory human review) usable for retrieval/training; every correction is AI feedback with accuracy metrics.
- Zero runtime dependencies (Node ≥ 22.13, built-in SQLite). Optional Claude integration via the official `@anthropic-ai/sdk` (`ANTHROPIC_API_KEY`, default model `claude-opus-5-5`); offline Arabic heuristic analyzer otherwise.
- Run: `node server.js` → `http://localhost:3000` (demo data and accounts are created automatically). Tests: `npm test`.
